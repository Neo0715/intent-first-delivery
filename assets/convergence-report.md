## 4. 缺口清单

> 这一步的输出就是缺口。**没有缺口也要写明「已核对无缺口」，不要留空。**

| # | 缺口 | 类型 | 严重度 | 处理决定 |
|---|---|---|---|---|
| 1 | | 功能缺失 / 行为不符 / 边界未处理 / 文档缺失 / 测试缺失 | 高/中/低 | 追加切片 / 记入后续（未决项） / 已接受偏差 |

**缺口类型说明**：

- **功能缺失** —— 契约要求了但完全没做
- **行为不符** —— 做了，但表现跟契约不一致
- **边界未处理** —— 主路径通了，异常路径没管
- **文档缺失** —— 产物没有可交接的说明
- **测试缺失** —— 没有能证明它工作的验证

## 7. 收敛判定

| 检查项 | 结果 |
|---|---|
| 契约验收标准是否全部有对应产物 | 是 / 否 |
| 缺口是否已全部处理，或已**逐条列入未决项/已接受偏差** | |
| 是否存在未记录的范围蔓延 | |
| 下一轮是否还有新缺口 | 有 / 无 |

**本轮结论**：`已收敛（无未决项）` / `已收敛（含 N 条已接受的偏差，逐条列出）` / `未收敛（缺口：___）`

> **「用户接受这个缺口」不等于缺口消失。** 只有两种下场：**修掉**，或者**变成一条写明的未决项**（谁接受、为什么接受、影响是什么）。因为它被接受了就从清单里划掉，「已收敛」就成了一句空话。
>
> 判定用词与验收证据保持一致：`已验证` / `失败` / `未验证`，不要另造一套。

**若已收敛** → 交付，进入 ⑤ 沉淀复用。
**若未收敛** → 带着缺口清单回到 ④ 4.1。
