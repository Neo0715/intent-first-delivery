# 速查卡 · 意图优先交付流程

> 一页版。贴给别的 agent 或自己扫一眼用。
> 完整流程见 `SKILL.md`。

---

## 核心问题

Agent 最常见的失败不是「不会做」，而是**没搞清要做什么就开始做**。返工成本在验收时才爆发。所以把成本前置到「问清楚」。

---

## 开场：先判体量（用大白话说出来，让用户可以推翻）

| 档 | 什么算描述清楚了 | 然后 |
|---|---|---|
| 一档 快速小事 | 请求本身就是完整描述 | 直接做（含不可逆步骤仍要取确认） |
| 二档 小改动 | 对话里说清楚 | 走 ①→③，产物留在对话里，不写正式文档；动手前一句话说出「怎么算做对了」 |
| 三档 要交付的项目 | **成文的意图契约** | 完整走 ①→⑤ |

各档的差别只在**产物形态**，不在要不要想清楚。

中途长大了就停下来说明并升档。是几个独立任务就分开做。**「我感觉挺清楚」不是判据。**

---

## 门禁 0（总开关）

**未完成①意图契约 + ③计划并获用户批准之前，禁止任何改变状态的操作。**

（写文件 / 跑命令 / 装依赖 / 发请求 / 提交 / 删除 —— 指的是改变**系统或产物状态**的动作）

**两类不算「改变状态」，不受门禁限制**：① 流程自身的产物（澄清清单/契约/计划/证据 —— 不写出来就没法被确认）；② 只读操作（读文件、搜代码、查文档、`git status`）。

**三种可豁免情形**（须一句话声明理由）：

1. **微小改动** —— 一句话可描述完的改动（改错别字、加一行日志）
2. **用户已授权** —— 用户明确说「直接做」（须列出全部假设供事后确认；①②③ 没被跳过的部分照走）
3. **紧急止损** —— 故障扩大中必须立刻回滚（事后补齐契约）

⚠️ 含**不可逆步骤**（删除、发布、付款、对外发送）的任务**不适用**第 1、2 种豁免，必须在契约里单独列出该步骤并单独取确认。

---

## 主线

```
① 接收诉求 ──> ② 理解问题 ──> ③ 拆分问题 ──> ④ 执行并验证 ──> ⑤ 沉淀复用
   ⏸停下等确认     写契约+独立复读     ⏸停下等批准      出示证据+收敛
```

---

## ① 接收诉求

- **非代码场景**：盘问到共识为止（没有测试兜底，模糊会一路带到成品）
- **代码场景**：根因 > 猜测。`复现 → 最小化 → 假设 → 插桩 → 修复 → 回归`
- 提问：**一轮问透（≤3–5 条、同一主题），不挤牙膏**、不给示例答案、不说流程术语
  - 具体化话术：「上次遇到这个情况是什么时候？」「如果只能做好其中一件，是哪件？」「**我要是弄错了哪一点，你会最难受？**」
- **回述确认**：每问到一块就复述回去 —— 200–300 字大白话，**明确区分「你说的」和「我猜的」**，结尾问「哪里不对、漏了什么」
- **产出**：澄清清单 → **停下来等确认**
- **这一停不能和 ③ 的停合并成一轮** —— 合并等于取消了意图确认点

---

## ② 理解问题

- **先搜再问**：官方文档/源码 → 实测 → 权威二手 → 博客（仅线索）
- 证据分级：`[已验证]` `[未核实]` `[待用户确认]`
- **查不到就说查不到，严禁编造** API / 版本号 / 数据 / 链接
- **产出**：意图契约（目标 / 边界 / **不做什么** / 验收标准 / 假设）
- **What 与 How 分离**：本阶段不写技术选型
- **独立复读（Builder-Check）**：给一个**无对话上下文的新 agent** 读契约，问「照这份文档能不能独立开工、哪里说不清」。它的问题分三堆：**已回答**→补进文档；**小事**→自己定并标注；**只有用户能答**→攒成一批一次问完。**回来之前不许交给用户说「确认吧」**

---

## ③ 拆分问题

- **垂直切片**，不是水平分层
  - ❌ 先写完所有 DB 层 → 再写所有业务层
  - ✅ 建表 + 一个接口 + 一个页面 + 测试（端到端打通一条）
- 每个切片必须**能独立验收**
- 切片粒度＝**一个动作 + 可检验的结果**（写失败测试 / 跑它确认失败 / 写最小实现 / 跑测试 / 提交）
- 切片清单 + PRD + 计划（含依赖、并行项、风险、回滚）
- **产出** → **停下来等批准**

---

## ④ 执行并验证

- 逐项执行，**偏离计划必须记录**，不许静默扩大范围
- **先立判据**：代码场景 —— 没写过失败测试，不许写实现（`红 → 绿 → 重构`）；非代码场景 —— 先写下「怎么算它做对了、什么证据能推翻我」，再动手。判据写不出来＝契约的验收标准不合格，退回 ②
- **双轴评审**
  - 规范轴：是否偏离计划/准则/既有模式
  - 需求轴：是否满足契约验收标准（**须由未参与实现的上下文跑**）
  - ⚠️ 只报影响正确性的问题。找缺口的评审者总会找出东西，追着修会过度工程
- **铁律：没有当场的新鲜证据，不许做任何完成性声明**
  - 五步门禁函数：**哪条命令能证明 → 完整跑一遍 → 读完整输出/退出码 → 输出真的支持吗 → 才开口**
  - 「这一轮没跑过那条命令，就不能说它通过了」；上一轮跑过不算、上次是好的不算
  - 常见混淆：测试通过要「0 个失败」的输出（不是「应该能过」）｜构建成功要退出码 0（不是「静态检查过了」）｜bug 修好要**复现原始症状那条测试**通过（不是「改了代码」）｜需求满足要**逐条核对**（不是「测试通过」）｜子 agent 干完要看 diff（不是「它说成功了」）
  - 危险词：「应该」「大概」「看起来没问题」、验证前先说「好了」
- **收敛**：实际产物比对契约 → 缺口追加为新切片 → 循环直到无新缺口

---

## ⑤ 沉淀复用

- 更新契约与决策记录（**有现成文档就更新，不要另起一份**）
- 记录踩过的坑、**被推翻的假设**（不记，下一个人会再撞一次）
- 目标是：换个 agent 接手，读完产物就能继续，不必看对话记录

---

## 可以跳过流程的情况

纯问答 / 一档任务 / 用户明确说直接做 / 探索性任务（须声明「这不是最终目标」）

## 绝不能跳过的情况

非代码场景 · 多文件多模块 · 用户说过「上次做出来的不是我想要的」· 交付物要给别人用 · 不可逆操作

---

## 进入 ④ 前的自检

- [ ] 目标一句话说清且用户认可
- [ ] **不做什么**已写明
- [ ] 验收标准可判定（非「好一点」「优化一下」）
- [ ] 假设已列出并确认，或用户明确接受风险
- [ ] 关键事实已查证或标注未核实
- [ ] **契约做过回述确认，用户亲口纠正过或确认过**
- [ ] **契约过了独立复读，「只有用户能答」那堆已一次问完**
- [ ] 已拆成可独立验收的切片
- [ ] 用户已批准计划

## 交付前的自检

- [ ] 每条验收标准都有证据
- [ ] 证据是原始输出，不是转述
- [ ] **每条「通过」都是本轮亲自跑出来的，没有沿用上次结果**
- [ ] 需求轴由未参与实现的上下文跑过
- [ ] 收敛比对做过，缺口已回流
- [ ] 失败项与残留风险已如实写出
