# 验收证据

> 阶段 ④ 执行并验证 的产物。
> 核心原则：**出示证据，不许声称成功。**
> 「已完成」「应该没问题」「已修复」不是证据。

---

## 1. 验收标准逐条对照

> 逐条对应 `intent-contract.md` 第 4 节的验收标准。**不许漏项，不许合并。**

| # | 验收标准（照抄契约） | 实际结果 | 证据编号 | 判定 |
|---|---|---|---|---|
| 1 | | | E1 | `已验证` / `失败` / `未验证` |
| 2 | | | E2 | |
| … | **契约里有几条就写几行，不许合并成一行** | | E3、E4… | |

**判定规则**：

- `已验证` —— 必须有对应证据，且证据是**原始输出**、用户能独立打开核对
- `失败` —— 如实写失败，并给出下一步。**报告失败比假装成功有价值得多**
- `未验证` —— 环境/数据缺失导致没跑。**不许把「未验证」写成「已验证」**
- 这三档是全流程**唯一**的判定用词。排查简报的回归判定、收敛报告的缺口判定都用这一套，不要另造词

**汇总**：__ 条 `已验证` / __ 条 `失败` / __ 条 `未验证`

**证据条数必须等于验收标准条数。** 一条「测试全过」不能同时证明三条标准 —— 那三条标准需要的证据，是三条各自能被独立核对的证据。

> ⚠️ 被要求「找缺口」的评审者总会找出东西 —— 因为那就是它的任务。**只处理影响正确性或既定要求的问题。**

> **不许把阻塞项改标成「可选」来让交付过关。** 判据是：这条不修，交付物是否直接违反契约里的某条验收标准？
> 是 → 阻塞；不是 → 才可选。**这个判断要写出来，不能只在心里做。**
