# intent-first-delivery — 触发评测报告（v6）

> 本报告所有可复算数字都来自 `evals/raw/` 下的原始判定器输出，可用 `evals/tools/score.mjs` 与
> `evals/tools/audit-current.mjs` 复算。没有原始输出支撑的历史数字，一律标为「不可独立复核」。

---

## 1. 口径：这是什么指标（先读这一节，再看任何数字）

判定器是**一个全新上下文的子 agent**，它只看技能目录里的 `name` + `description`
（外加一个无关干扰技能），不读技能正文、不用工具、不执行任务，只回答：
「这条用户消息是否应当加载这个技能」。每条消息独立判 3 次，触发率 ≥ 0.5 记为「触发」。

因此本目录所有数字都是 **【描述分类代理指标】**：

- 它测的是 **`description` 这段文字本身的判别力**；
- 它 **不是** 目标 agent 在真实会话里的**实际触发率**；
- 它也 **不是** 触发率的**下界**——真实 agent 完全可能不加载技能就直接开工。
- 本环境没有可编程的 agent 运行器（`claude -p` 那样的非交互入口），**测不了真实端到端触发率，所以不声称测了**。

## 4. `description` 迭代史（v1 → v6）

`description` 是唯一的触发机制（官方：`description` 是 primary trigger）。**每一版分数只描述那一版。**

| 版 | 字符 | 改动 | 结果 | 可复核 |
|---|---|---|---|---|
| v1 | 388 | 初版：要产出东西就得走流程 + 情形清单 | 作者记录 train 12/13、valid 7/9 | ❌ 无原始输出 |
| v2 | — | 加「用户已说全就照做」边界句（想修 N6） | 作者记录 13/13、8/9 | ❌ validation 文件与 v1 逐字节相同 |
| v3 | — | 换成单一判据「还有没有得靠猜的决定」 | 作者记录 13/13、7/9 | ❌ 无原始输出 |
| v4 | 388 | 「先取证」改为不能当动作执行的门禁 +「目标 ≠ 标准」 | **21/22**（train 13/13、valid 8/9，仅 N9） | ✅ `raw/v4/` |
| v5 | 469 | + 探索不是后门（合规修复）+「批量或不可逆」 | 迭代 **21/22**（N9）；回归 10/12（N13、N14） | ✅ `raw/v5-raw.txt` |
| **v6（发布）** | **467** | 去掉「批量」只留「不可逆」 | 迭代 **19 / 20 / 22**（3 轮）；回归 10/12；泛化 8/10 | ✅ `raw/v6-*.txt`、`raw/gen-v6-raw.txt` |

**v5→v6 的唯一差异**（逐字见 `raw/descriptions.txt`）：
「批量或不可逆的操作，哪怕范围看起来清楚（…，范围、可逆性、误伤面要当面确认）」
→「不可逆的操作，哪怕范围看起来清楚（…）——范围、可逆性、误伤面要当面确认」。

改动的**动机**是想让「批量但可逆、且范围/动作已说全」的机械任务（如全仓重命名）不再误触发。

> ⚠️ **但这条动机没有被证据支持**：N14（全仓重命名）在 v6 下**仍然 3/3 误触发**，
> 且判定器给出的理由指向的是**「跨多个文件」**这条子句，不是被删掉的「批量」。
> 详见第 6.2 节。这属于「改动理由未被证实」，本报告如实记下，不粉饰。

## 9. 复现方式

```bash
# 在技能根目录下执行：
node evals/tools/validate-spec.mjs .        # 规范机械条款自检（三档：规范要求/官方建议/自定义）
node evals/tools/score.mjs evals/raw/v6-raw.txt        # 给某份原始输出打分（三集合自动分流）
node evals/tools/score.mjs evals/raw/v6-run2-raw.txt   # 只含迭代集的输出同样能打分
node evals/tools/audit-current.mjs .        # 核对当前发布 description 是否就是被评测的那段，并复算
node evals/tools/variance.mjs evals/raw/v6-raw.txt evals/raw/v6-run2-raw.txt evals/raw/v6-run3-raw.txt
                                            # 同一版本多轮运行之间的翻转项与通过数范围
```

`score.mjs` 会自动合并三个查询集（迭代集 + 回归集 + 泛化集），并按每个集合的
`should_trigger` 分别统计；它还会检查每条查询是否凑满 `defaults.runs_per_query` 次试次，
**试次缺失时拒绝给出通过结论**。

`audit-current.mjs` 会打印当前 `description` 的 SHA-256，并报告它匹配
`evals/raw/descriptions.txt` 里的哪一版、对应哪份原始输出——**改过 `description` 之后，
它会立刻告诉你「这段文字没被评测过」**。改完描述务必重跑它。

## 10. 已知局限（如实列出）

1. **代理指标，非端到端触发率**（第 1 节）——判定器只模仿「要不要加载技能」这一步，
   回答不了「加载后行为是否达标」。
2. **同版本 3 轮的观测散布为 19–22，且单条查询会翻转**（第 7 节）；
   这只是观测范围，不是方差估计。
3. **v5 与 v6 不可比**——各轮次数不同，无法把描述改动与判定器噪声分开。
4. **v6 的改动理由（N14）未被证据支持**（第 4、6.2 节），已如实记录。
5. **输出质量对照未达 3 次/格**（第 8 节）。
6. **历史数字 v1/v2/v3 不可复核**，且 v2 存在数据完整性错误（第 3 节）。
7. **判定器模型标识不可核实**（见 `raw/run-manifest.md`）——包内无证据支撑任何具体模型名。
8. **「skillhub_search 工具在本会话不可用」这一历史陈述**：本次会话找不到任何可查证的记录，
   只能标注为「据称，无记录可查」。
9. **泛化集只有一次运行**（1 轮 3 试次/条），未做多轮复跑；其 8/10 与 6.2 的结论都以这一轮为限。
